# Code Style

## Comments
- Write at most 1 line comment per block — short and crisp, no definitions
- Less is more: if the code is self-explanatory, skip the comment entirely

## Design & Implementation
- Always follow the agreed design before implementing anything
- If the design for a piece of work is unclear or not yet discussed, **stop and ask** — do not infer or improvise
- Never add features, abstractions, or structure beyond what the current design specifies
